# Ломающийся шаблон отчёта — «где ломается»

Данные вымышленные, компания «Меридиан» не существует.

Учебный шаблон: тот же документ «Отчёт об отгрузках» компании «Меридиан»,
но структура сделана иначе, чем в нейтральном `../skill-skeleton/templates/report-template.docx`,
и именно эта разница должна ломать `fill_report.py`:

1. **Колонтитулы с полями компании.** Верхний и нижний колонтитулы (`section.header`,
   `section.footer`) несут текст с названием компании и плейсхолдером периода. Скрипт читает
   только тело документа (`doc.paragraphs`, `doc.tables`) — плейсхолдер в колонтитуле остаётся
   незаполненным, а зритель видит его на экране рядом с готовым телом отчёта.
2. **Двухуровневая шапка таблицы.** Первая строка таблицы — одна объединённая ячейка на всю
   ширину («ОТЧЁТ ОБ ОТГРУЗКАХ»), вторая строка — обычные подписи столбцов. Скрипт эталонного
   скилла клонирует «последнюю строку» шаблона как строку данных; лишняя строка сверху меняет,
   какая строка окажется последней в других раскладках того же приёма.
3. **Объединённые ячейки в строке данных.** Ячейки «Клиент» и «Товар» слиты в одну. В
   `python-docx` слитая ячейка отдаёт один и тот же объект на обе исходные позиции сетки —
   подстановка по индексу колонки (`cells[1]`, `cells[2]`) пишет два разных значения в одну и ту
   же ячейку, и последнее перезаписывает первое.

**Подтверждено прогоном на практике.** Пункт 1 и пункт 2 воспроизведены реально: в собранном
файле «Клиент» и «Товар» получают одинаковый текст (слитая ячейка отдаёт один и тот же объект
на обе позиции), а лишняя верхняя строка шапки таблицы попадает в отчёт как строка данных.
Провал проявляется по-разному от прогона к прогону: один раз модель распознаёт несовместимость
шаблона заранее и останавливается с вопросом, не запуская скрипт; другой раз запускает скрипт,
рапортует об успехе и отдаёт файл с этими дефектами, не заметив их сама — именно второй вариант
нагляднее, потому что расхождение видно только при сравнении с исходными данными, а не в самом
ответе модели.
